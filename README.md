# Free Stars ✨

Telegram Mini App: рулетка подарков 🧸 🎂 ❤️ с бесплатным ежедневным спином,
дополнительными вращениями за **5 Telegram Stars**, гарантированным подарком
на 31-й день серии, историей выигрышей, уведомлениями владельцу и закрытой
админ-панелью с финансовой аналитикой и контролем риска.

Дизайн: тёмное золото / казино — чёрный фон, золотые градиенты, сектора колеса
чередуются чёрный ↔ золотой, номер выигрыша вида `FS-123456`.

Владелец проекта: **@maxxm4z** — <https://t.me/maxxm4z>
Бот: **@FreeStarsverygoodbot**

## 1. Что реализовано

| Требование | Где реализовано |
|---|---|
| Серверный выбор результата (клиент не может повлиять) | `server/roulette.js` (`crypto.randomInt`), `server/game.js` |
| Шансы 🎂 1% / 🧸 3% / ❤️ 3% / 🍃 93% | `server/roulette.js`, меняются в админке |
| Один бесплатный спин в сутки по времени сервера | `server/game.js` → `spinFree`, поле `users.free_spin_day` |
| Защита от повторных и одновременных запросов | `tx()` c `BEGIN IMMEDIATE` + проверка `free_spin_day` |
| Платный спин за 5 Stars (XTR) | `server/payments.js` → `createStarsInvoiceLink`, `handleSuccessfulPayment` |
| Обработка `pre_checkout_query` | `server/payments.js` → `validatePreCheckout` |
| Защита от повторной обработки платежа | `payments.telegram_charge_id UNIQUE`, `payments.spin_id`, `handleSuccessfulPayment` |
| Возврат Stars, если спин не выдан | `refundStarPayment` в `deliverSpin` |
| Гарантия на 31-й день | `server/game.js` → ветка `kind = 'guarantee'` |
| Уникальный номер выигрыша `FS-123456` | `generateWinCode()` + `wins.win_code UNIQUE` |
| Уведомление владельцу с повторами | `server/notify.js` (очередь + backoff), `notify_queue.win_id UNIQUE` |
| История «Мои выигрыши» | `server/game.js` → `userHistory`, `public/app.js` |
| Админ-панель | `server/admin.js`, `public/admin.html` |
| Вероятности в админке (сумма 100, журнал) | `validateProbabilities`, `probability_history` |
| Финансовая аналитика и прогноз 100/500/1000/5000 | `server/finance.js` → `finance`, `forecast` |
| Контроль риска и остановка новых спинов | `server/finance.js` → `riskReport`, `setToggle` |
| Ручное подтверждение выдачи | `POST /api/admin/wins/:id/deliver`, `/:id/cancel` |
| Валидация `initData` на сервере | `server/auth.js` (HMAC-SHA256 + Ed25519 при наличии ключа) |

Архитектура: один Node.js-процесс (Express + встроенный `node:sqlite`),
без сборки фронтенда, без внешней базы данных. База создаётся автоматически.

## 2. Правила и экономика

**Механика**

- Один **бесплатный** спин в сутки по времени сервера (`SERVER_TZ_OFFSET_HOURS` задаёт часовой пояс).
- Дополнительный спин — **5 ⭐** (Telegram Stars, валюта `XTR`).
- Шансы: 🎂 Торт «Мерцание» 1%, 🧸 Мишка 3%, ❤️ Сердце 3%, 🍃 Ничего 93%. Сумма ровно 100%.
- Пустой результат: «В этот раз без подарка. Попробуй снова завтра!». Запись о выигрыше не создаётся.

**Гарантия (зафиксировано в правилах)**

- Считаются **только бесплатные** ежедневные спины. Платный спин не увеличивает прогресс.
- Один календарный день засчитывается один раз (по времени сервера).
- Пропуск дня обрывает серию: прогресс и признаки серии обнуляются.
- На **31-й день непрерывной серии**, если в этой серии ещё не было выигрыша, выдаётся
  **гарантированный подарок — 🎂 Торт «Мерцание»**.
- Гарантия даётся **один раз за серию** и не может быть отменена настройкой обычных вероятностей:
  её ветка обрабатывается отдельно от `rollOutcome()`.
- Если подарок уже выпал в серии (любым спином) — гарантия не выдаётся, чтобы не выдавать
  два подарка за одну серию.

**Внутренняя оценка подарков** (задана владельцем, **не** является официальной ценой Telegram Gifts):
🧸 15 ⭐ · ❤️ 15 ⭐ · 🎂 50 ⭐.

**Выдача.** Статус «Выдан» ставится **только вручную** владельцем в админке. Отправка ссылки
@maxxm4z или открытие приложения не подтверждают выдачу. Причину отмены сохраняем, историю не удаляем.

## 5. Подключение Mini App и Telegram Stars

### 5.1. Что нужно сделать один раз вручную

1. **Создать бота** у [@BotFather](https://t.me/BotFather) → получите `BOT_TOKEN`.
2. **Узнать числовой Telegram ID владельца** — владелец отправляет боту `/start`,
   затем запускается `npm run owner:id @<username>`, и полученный ID вписывается
   в `OWNER_TELEGRAM_IDS`.
   Панель проверяет **числовой ID**, а не username: переименование аккаунта не даст доступа.
3. **Поднять HTTPS-адрес.** Telegram открывает Mini App только по HTTPS.
   Локально: `.\tools\cloudflared.exe tunnel --url http://localhost:3001` или `ngrok http 3001` →
   полученный адрес впишите в `PUBLIC_URL`.
   Для постоянной работы используйте обычный хостинг/VPS с сертификатом.
4. **Настроить бота:**

```bash
node server/setup-bot.js              # команды, кнопка меню, описание
node server/setup-bot.js --webhook    # + webhook для приёма платежей (нужен HTTPS)
node server/setup-bot.js --no-webhook # вернуть long polling
```

   Скрипт выведет сгенерированный `WEBHOOK_SECRET` — впишите его в `.env`.

### 5.2. Как это работает

- **Кнопка в боте.** `/setup-bot` ставит кнопку меню типа `web_app` на адрес `PUBLIC_URL`.
  Пользователь жмёт кнопку и открывает Mini App внутри Telegram.
- **Платёж.** Клиент просит у сервера счёт → сервер вызывает `createInvoiceLink`
  (`currency: "XTR"`, `provider_token: ""`, `prices: [{ amount: 5 }]`).
  Клиент открывает ссылку (`Telegram.WebApp.openLink`), Telegram показывает лист оплаты.
- **Подтверждение.** Бот получает `pre_checkout_query` и `successful_payment`
  (через webhook или long polling). Ответ на `pre_checkout_query` формируется **только** из
  серверной цены, валюты и владельца счёта. Спин создаётся в одной транзакции с
  `UPDATE payments ... WHERE status='created'`, поэтому повторное событие — no-op.
- **Спин не выдан** (ошибка/сбой) → автоматический `refundStarPayment`.
- **Клиент не доверенный.** Клиент может получить только `invoiceUrl`; сумму, валюту и
  payload задаёт сервер. Клиент не может получить спин без записи в БД со статусом `paid`.
- **Запасной канал.** Если webhook недоступен, клиент дёргает `/api/spin/paid/reconcile`,
  сервер сверяет платёж через `getStarTransactions` и обрабатывает его.
- **Stars-рефанд.** Telegram не возвращает Stars автоматически — это делает бот через
  `refundStarPayment` в течение 48 часов, поэтому важно следить за журналом платежей.

## 6. Админ-панель

Адрес: `PUBLIC_URL/admin` (внутри Telegram). Доступ — только при валидном `initData`
и `tg_id` из `OWNER_TELEGRAM_IDS`; проверка выполняется на **каждом** запросе.

Вкладки:

- **Статистика** — пользователи (всего / новые / активные 24 ч и 7 дней), спины (все / бесплатные /
  платные / гарантированные / пустые), выигрыши по видам, статусы выдачи, полученные и возвращённые Stars.
- **Выигрыши** — фильтры по датам, статусу, типу спина; поиск по номеру выигрыша, Telegram ID и
  `@username`; кнопки «Выдан» и «Отмена» (с обязательной причиной); экспорт CSV.
- **Платежи** — все счета: сумма, валюта, статус, выдан ли спин, ошибка, дата.
- **Вероятности** — редактирование 1/3/3/93 с проверкой суммы = 100 и запретом отрицательных
  значений; предупреждение о последствиях; журнал «было → стало» с ID администратора.
  Изменения применяются только к новым спинам (каждый спин хранит снимок вероятностей).
- **Финансы** — поступления, возвраты, стоимость выданных и ожидающих подарков по видам,
  оценка обязательств по гарантии, расчётный результат, точка безубыточности,
  реальные транзакции Telegram (`getMyStarBalance`, `getStarTransactions`) и **прогноз**
  по сценариям 100 / 500 / 1 000 / 5 000 пользователей.
- **Риск** — уровень обязательств, настраиваемый бюджет, переключатели «новые вращения» и
  «платные спины».
- **Журналы** — действия администратора и ошибки сервера.

Все действия администратора записываются в `admin_log`.

## 6.1. Деплой 24/7 (Koyeb)

### Важно про хранение данных

Koyeb Free — это **1 веб-сервис: 512 МБ RAM, 0.1 vCPU, 2 ГБ SSD**, регион
Франкфурт или Вашингтон. Локальный диск там **эфемерный**: данные могут пропасть
в любой момент, а инстанс переносится на другой сервер минимум раз в неделю
при автообновлениях. Сервис засыпает после ~1 часа без трафика и просыпается
за 0.5–5 секунд.

Что это значит для проекта:

- SQLite-база (`data/freestars.db`) **будет стираться**. Схема и настройки
  создаются автоматически при старте, сервер поднимается сам — но пользователи,
  выигрыши и история платежей сбросятся.
- **Платные спины при этом ломаются**: `pre_checkout_query` / `successful_payment`
  привязаны к записям в БД, и после сброса оплата не сможет превратиться в спин
  и вернуться.
- Поэтому бесплатный Koyeb годится на демо и тесты, но **не для приёма Stars**.

Что делать, если всё же разворачиваете на Koyeb:

1. Выгружать базу вручную до каждого обновления: `GET /api/admin/export/db.sqlite`
   (доступно владельцу) — это же готовая копия для переноса на другой хостинг.
2. Ежедневные копии сервер делает сам в `data/backups/`, но на эфемерном диске
   они исчезают вместе с базой.
3. Надёжный 24/7 с постоянным диском — платный инстанс Koyeb с Volume,
   либо Fly.io / Railway / Oracle Cloud Free VM.

### Порядок деплоя

1. **Залить код в Git** (Koyeb собирает из репозитория). `.env`, `data/` и
   `logs/` в `.gitignore` — секреты в репозиторий не попадут.

   ```bash
   cd путь/к/бот2
   git init
   git add .
   git commit -m "Free Stars: Telegram Mini App roulette"
   git remote add origin https://github.com/<ваш-логин>/free-stars.git
   git push -u origin main
   ```

2. **Создать сервис на Koyeb**: <https://app.koyeb.com> → *Create Service* →
   *GitHub* → выбрать репозиторий. Сборка пойдёт из `Dockerfile`
   (`node:24-slim`, порт `3001`).

3. **Задать переменные окружения** (Variables):

   | Ключ | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от @BotFather |
   | `OWNER_TELEGRAM_IDS` | `6997217909` |
   | `OWNER_USERNAME` | `maxxm4z` |
   | `BOT_USERNAME` | `FreeStarsverygoodbot` |
   | `APP_NAME` | `Free Stars` |
   | `PORT` | `3001` |
   | `PUBLIC_URL` | адрес вида `https://<сервис>-<орг>.koyeb.app` |
   | `WEBHOOK_SECRET` | сгенерированная строка |

   `PUBLIC_URL` известен только после первого деплоя — поставьте его вторым шагом.

4. **Настроить бота** (локально, в папке проекта):

   ```bash
   node server/setup-bot.js --webhook
   ```

   Скрипт выведет `WEBHOOK_SECRET` — впишите его в переменные Koyeb
   и сделайте редеплой. Скрипт также поставит кнопку меню Mini App.

5. **Проверить**: `https://<домен>/health` отвечает, кнопка меню открывает
   приложение, админка на `/admin` доступна владельцу.

## 8. Тесты

```bash
npm test
```

88 тестов, все проходят. Что проверяется:

- **Вероятности** (`tests/roulette.test.js`): сумма ровно 100, отклонение отрицательных,
  неизвестных и дробных значений, единицы веса, распределение на **400 000 спинов**
  (1% / 3% / 3% / 93% в пределах 4σ), детерминированные 0% и 100%.
- **Авторизация** (`tests/auth.test.js`): подпись initData, подмена `user` и `auth_date`,
  чужой токен, устаревшие данные, права строго по числовому ID.
- **Игровая логика** (`tests/game.test.js`): один бесплатный спин в сутки, защита от
  повторных запросов, обрыв серии, пустой результат без выигрыша, **гарантия на 31-й день
  при нулевых шансах**, одна гарантия за серию, отмена гарантии при раннем выигрыше,
  новая гарантия в новой серии, независимость платного спина от серии, запрет повторного
  использования платежа, уникальность номера выигрыша, отсутствие дублей уведомлений.
- **Платежи** (`tests/payments.test.js`): повторное событие не выдаёт второй спин,
  `UNIQUE` по `telegram_payment_charge_id`, подмена суммы/валюты, чужая оплата,
  серверная проверка `pre_checkout_query`, видимость статуса только своему пользователю.
- **Финансы** (`tests/finance.test.js`): внутренние стоимости 15/15/50, подсчёт подарков,
  расходы по статусам, фильтр по датам, оценка обязательств по гарантии,

  уровни риска, остановка новых спинов без потери выигрышей.

## 9. Ограничения Telegram Bot API

- **Настоящие подарки Free Stars отправить нельзя.** `sendGift` работает только с
  подарками из официального каталога Telegram (`getAvailableGifts`). Мишка, Торт «Мерцание»
  и Сердце — авторские изображения, их нет в каталоге, поэтому выдача идёт **вручную через
  @maxxm4z**. Картинка в Mini App — визуал, а не Telegram Gift.
- Если владелец сопоставит подарки с реальными `gift_id` и включит `AUTO_ISSUE_GIFTS=1`,
  сервер попробует отправить настоящий Gift через `sendGift` и запишет результат.
  Статус «Выдан» всё равно подтверждает человек.
- `createInvoiceLink` не работает в тестовом окружении и требует реального бота.
- Webhook требует публичный HTTPS и не больше одного параллельного `getUpdates`:
  либо webhook, либо long polling, либо внешний сервер Bot API.
- Bot API не показывает вывод Stars на сторону владельца — данные о фактических расчётах
  доступны только владельцу. Панель показывает баланс бота и входящие транзакции.
- `initData` не содержит данных об устройстве: защита от смены часов обеспечивается тем,
  что «серверный день» считает сервер, а таймер в интерфейсе — только отображение.

## 10. Финансовые риски

Честная арифметика при базовых настройках (шансы 1/3/3/93, бесплатный спин каждый день,
3 платных спина на пользователя, гарантия 50 ⭐ на 31-й день):

| Сценарий | Доход | Ожидаемые расходы | Результат |
|---|---|---|---|
| 100 юзеров, 30 дней | 1 500 ⭐ | 4 620 ⭐ | **−3 120 ⭐** |
| 100 юзеров, 90 дней | 1 500 ⭐ | 22 697 ⭐ | **−21 197 ⭐** |
| 1 000 юзеров, 30 дней | 15 000 ⭐ | 46 200 ⭐ | **−31 200 ⭐** |
| 1 000 юзеров, 90 дней | 15 000 ⭐ | 226 974 ⭐ | **−211 974 ⭐** |

(Это те же числа, что выдаёт `GET /api/admin/forecast`; расходы = обычные выигрыши + гарантия.)

Причина: **гарантия на 31-й день** обещает подарок каждому активному пользователю
(≈50 ⭐ на человека), а доход (5 ⭐ за платный спин) и редкие выигрыши его не покрывают —
безубыточность достигается примерно при **9 платных спинах за 30 дней** или **45 за 90 дней**
на пользователя. Проект **не гарантированно прибылен** — при этих правилах он убыточен,
и панель это показывает прямо.

Что делать:

- Поднять цену дополнительного спина (переменная `SPIN_PRICE_STARS`) или убрать гарантию —
  обе настройки меняются на сервере и применяются к новым спинам.
- Следить за разделом «Риск»: при превышении бюджета отключить платные спины
  (уже выигранные подарки сохраняются и выдаются).
- Понимать, что внутренние стоимости подарков (15/15/50 ⭐) — оценка владельца, а не
  официальный курс и не денежный остаток.

## 11. Что нужно сделать вручную

1. Получить `BOT_TOKEN` у @BotFather.
2. Узнать числовой Telegram ID владельца и вписать `OWNER_TELEGRAM_IDS`.
3. Купить/получить HTTPS-домен, заполнить `PUBLIC_URL`.
4. Выполнить `node server/setup-bot.js` и (для платежей) `node server/setup-bot.js --webhook`,
   затем вписать выведенный `WEBHOOK_SECRET` в `.env` и перезапустить сервер.
5. Проверить в Telegram: кнопка меню открывает Mini App, кнопка «Крутить бесплатно» работает,
   кнопка «Ещё спин — 5 ⭐» открывает лист оплаты Stars.
6. При тестовом выигрыше убедиться, что владельцу пришло уведомление и в админке появилась
   запись со статусом «Ожидает выдачи»; после реальной выдачи нажать «Выдан».
7. Заполнить желаемый бюджет в разделе «Риск».
